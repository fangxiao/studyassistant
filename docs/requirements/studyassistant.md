## 1. 背景与问题

自学者在学习一个新领域时普遍遇到三个断点：

1. **不知道学什么、按什么顺序学** —— 拿到一个目标（如「搞懂 Transformer」「学会 Rust 所有权」），无法自行拆解为有序、可执行、颗粒度合适的知识点序列。
2. **没有人验证是否真的学会** —— 看书、看视频会产生「我懂了」的错觉。缺少强制输出与检验环节，知识停留于熟悉感而非可调用状态。
3. **卡住即放弃** —— 某个知识点用第一种讲法没听懂，没有第二种讲法，学习链条中断。

市面上多数「AI 学习助手」止步于第 1 点（生成一份计划/大纲）或第 2 点（出几道题），**没有把「没学会 → 换一种讲法 → 再验证」这个循环真正闭环**。

## 2. 产品定位

把 AI 定位为**一对一私教老师**，围绕**单一学习目标**提供完整闭环：

```
目标 → 知识树计划 → ┌─ 讲解 → 出题验证 → 判分诊断 ─┐
                    │      未达标 → 换角度重讲 ────┤
                    └────── 达标 → 解锁下一知识点 ──┘
                              ↓
                        全部达标 → 学习报告 + 错题本
```

**核心差异点：AI 不通过「讲完了」结束，只通过「你答对了」结束。**

## 3. 目标用户与典型场景

| 用户 | 场景 |
|---|---|
| 应试备考者 | 「两个月内掌握考研数学线性代数」，需要按考纲拆解并反复检验薄弱点 |
| 转行/技能补强者 | 「搞懂 Kubernetes 网络模型」，需要从零建立知识结构 |
| 在校学生 | 「学会这章教材」，手上有 PDF 讲义，希望基于讲义讲解与出题 |
| 企业培训 | 「掌握内部风控流程」，需要基于私有知识库出题，答案可溯源 |

## 4. 用户故事

**计划阶段**

- **US-1** 作为学习者，我想告诉老师我的学习目标、当前基础水平和每天可投入的时长，以便得到一份匹配我实际情况的计划。
- **US-2** 作为学习者，我想看到目标被拆解成有序的知识点清单（含每个点的预估耗时与「怎样才算学会」的验收标准），以便知道全貌和进度。
- **US-3** 作为学习者，我想在开始前确认或调整这份计划，以免方向跑偏。

**学习阶段**

- **US-4** 作为学习者，我想让老师一次只讲一个知识点，用「直觉 → 定义 → 例子 → 类比 → 常见误区」的层次展开，而不是一次性倒给我一大段。
- **US-5** 作为学习者，遇到抽象概念时我想让老师生成一张示意图，以便建立直观理解。
- **US-6** 作为学习者，我想基于自己的教材/讲义（PDF）或私有知识库学习，并且老师的讲解与题目能给出原文出处，以便核对。

**验证阶段**

- **US-7** 作为学习者，我想通过点击选项或填写答案来作答（而不是只能打字聊天），以便快速完成检验。
- **US-8** 作为学习者，我想在答错后立刻知道**错在哪个子概念**、为什么错，而不是只被告知「答错了」。
- **US-9** 作为学习者，当我没学会时，我想让老师**换一种讲法**（换类比、换图示、换实例、换严谨推导）再讲一遍，而不是把同样的话重复一遍。
- **US-10** 作为学习者，当某个知识点反复讲多次仍不达标时，我想让老师把它**拆成更小的子知识点**逐个攻克，而不是死磕。

**追踪阶段**

- **US-11** 作为学习者，我想随时查看整体进度、各知识点掌握度和错题本。
- **US-12** 作为学习者，我想关掉会话后下次还能「继续学上次的」，不必重新建档。
- **US-13** 作为学习者，我想在阶段性完成后拿到一份学习报告，以便复盘。

## 5. 验收标准

| 编号 | 验收标准 | 验证方式 |
|---|---|---|
| AC-1 | 输入学习目标 + 基础水平 + 每日时长后，产出结构化知识树，每个知识点含 `id / 标题 / 顺序 / 难度 / 预估耗时 / 验收标准` | 单测 + 人工冒烟 |
| AC-2 | 知识树持久化落盘；新会话中可加载既有计划并定位到当前知识点 | 单测（跨进程重载） |
| AC-3 | 每个知识点状态机为 `pending → learning → mastered`（另有 `skipped` 跳过、`split` 已拆解两个终态），仅当达标或已跳过才允许推进到下一个 | 单测 |
| AC-4 | 客观题（单选/多选）判分**完全确定性**，不依赖模型输出 | 单测（同输入必同输出） |
| AC-5 | 掌握度由确定性算法计算：题型加权得分率 × 尝试次数惩罚，输出 `[0,1]` 分数与 `pass/fail` | 单测（边界值） |
| AC-6 | 存在高权重题型（简答/应用）门槛：此类题得分率低于阈值时，即使总分达标也判 `fail` | 单测 |
| AC-7 | 未达标时返回 `action=reteach` 并指定一个**尚未使用过的讲解角度** | 单测 |
| AC-8 | 同一知识点重讲轮次超过上限时返回 `action=split`，建议拆解为更小颗粒度子知识点；拆解层数也触顶时返回 `action=skip`，标记薄弱点并允许推进 | 单测 |
| AC-9 | 讲解技能支持至少 6 种角度：直觉类比 / 图示 / 实例推演 / 严谨定义 / 对比辨析 / 追问引导 | 人工冒烟 |
| AC-10 | 抽象概念场景下可调用生图能力产出示意图 | 人工冒烟 |
| AC-11 | 可基于上传 PDF 与挂载知识库进行讲解与出题，并给出出处 | 人工冒烟 |
| AC-12 | 错题本记录每道错题的知识点、错因、正确答案 | 单测 + 人工冒烟 |
| AC-13 | 学习报告汇总：总进度、各知识点掌握度、薄弱点 Top-N、建议下一步 | 人工冒烟 |
| AC-14 | 计划/答题/讲解过程通过富交互控件呈现（表单、单选、多选、文本域、确认框、表格、折叠面板） | 人工冒烟 |

## 6. 非功能约束

| 类别 | 约束 |
|---|---|
| 架构边界 | 严格遵守平台 Client-Server 解耦；不得读取或修改平台源码；不得安装服务端依赖（sqlalchemy/asyncpg/fastapi/redis 等） |
| 依赖范围 | 仅 `agentplatform` + `pyyaml` + `pytest`（+ `pytest-asyncio` 开发依赖） |
| 复用优先 | 平台已有能力（PDF 解析、知识库检索、摘要、结构化输出、生图、联网搜索）一律复用，不自行实现 |
| 可测试性 | 所有确定性逻辑（判分、掌握度、状态流转、角度轮换）必须有 pytest 单测覆盖 |
| 状态隔离 | 状态文件路径支持环境变量覆盖，默认落于用户主目录，避免污染插件工程目录 |
| 数据安全 | 学习数据仅存本地，不外发；不采集个人身份信息 |
| 幂等与容错 | 状态文件损坏/缺失时降级为「无计划」并提示重建，不得崩溃 |

## 7. 明确不在本期范围

- 多用户/多租户与账号体系（以本机单学习者为主，`plan_id` 预留多计划能力）
- 学习提醒推送、日历集成
- 语音交互、口试模拟
- 题库导入导出、与外部 LMS 对接
