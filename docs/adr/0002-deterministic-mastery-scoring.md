# ADR-0002: 掌握度由确定性加权算法判定，不由模型主观裁定

- 状态: 已接受
- 日期: 2026-09-28
- 决策者: 用户（选型确认）+ AI 研发伙伴

## 背景

本插件的核心承诺是「**没学会就一直讲，直到你学会为止**」。这个承诺成立的前提是「学会」有一个**可复现、可解释、不可被讨好**的判定标准。

若把判定交给模型（让模型说「你已经掌握了」），会出现三个问题：

1. **讨好倾向** —— 模型倾向顺着用户说「你理解得不错」，闭环会提前退出，产品承诺失效。
2. **不可复现** —— 同样的作答两次问，可能得到不同结论，掌握度分数失去意义。
3. **不可测试** —— 无法写单测，无法回归，无法调参。

同时，若完全排除模型，则开放题（简答、推导、应用题）无法评分，而这类题恰恰是「真会」的最强信号。

## 决策

采用**混合职责**：

- **模型**：只负责两件事 —— 生成题目（含标准答案与评分要点）、依据评分要点给主观题打 `0~1` 的分。
- **工具**（`tools/_mastery.py`，纯函数、无 IO）：负责**聚合成掌握度、执行达标判定、决定下一步动作**。

算法（详见设计文档 §3）：

```
mastery = 加权得分率 × 尝试次数惩罚
verdict = mastery ≥ 阈值  且  高权重题型平均得分率 ≥ 门槛
```

- 题型权重：`single=1.0 / multi=1.4 / short=2.0 / apply=2.5`
- 尝试惩罚：`max(0.7, 1 - 0.1×(round-1))`
- **高权重题型门槛**：简答/应用类题平均得分率低于 0.6 时，即使总分达标也判 `fail`

## 理由

- **抗讨好**：判定权在纯函数里，模型无法通过措辞让用户「过关」。
- **抗刷分**：高权重门槛确保不能靠答对一堆选择题蒙混；尝试惩罚确保「反复试到过」的代价递增。
- **可解释**：`0.70 = 0.78 × 0.9`，失败原因逐条列出（`fail_reasons`），用户知道差在哪。
- **可测试**：纯函数 + 无 IO，边界值（空题、满分、全错、门槛擦边、轮次惩罚下限）全部可单测。
- **职责对齐平台分层**：`skills/` 放 Prompt 思考链，`tools/` 放确定性计算 —— 本决策正是这条红线的直接落地。

## 后果

**正面**
- 「学会」有客观标准，产品承诺可兑现、可回归。
- 分数可用于进度表、学习报告、薄弱点排序，数据一致。

**负面 / 代价**
- 阈值与权重是**超参**，需要凭经验设定并留可配置入口。
  - 缓解：全部放入 `config`（`mastery_threshold` / `heavy_type_floor` / `heavy_types` / `max_reteach_rounds`），计划创建时可覆盖。
- 主观题评分仍依赖模型，存在漂移。
  - 缓解：评分要点分档（0 / 0.3 / 0.6 / 1.0）降低自由度；主观题在总分中权重高但非唯一，客观题提供稳定基线。

## 备选方案

| 方案 | 放弃原因 |
|---|---|
| 完全由模型判定 | 讨好倾向导致闭环提前退出；不可复现、不可测试 |
| 完全排除模型（只出客观题） | 无法评估推导/应用能力，而这是「真会」的最强信号 |
| 纯正确率（不加权、不惩罚） | 可被选择题刷分；反复重试无成本，闭环失去收敛压力 |
