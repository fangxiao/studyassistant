# ADR-0001: 学习进度采用插件内置状态工具落盘

- 状态: 已接受
- 日期: 2026-09-28
- 决策者: 用户（选型确认）+ AI 研发伙伴

## 背景

「计划 → 讲解 → 验证 → 未过重讲」是一个**跨会话的长周期闭环**。用户关掉会话后再次打开，必须能接上「上次学到哪、哪个点卡住了、试过哪些讲法」。这要求进度可持久化。

平台提供三种可选路径：

1. **仅会话上下文** —— 状态只活在当前对话的模型上下文里。
2. **平台 `tool:memory`** —— 长期记忆，适合存偏好与事实，以自然语言条目为主。
3. **插件内置状态工具** —— 插件自己维护结构化状态文件。

## 决策

采用**方案 3：新增 `tool:learning_state`，将学习计划与进度以 JSON 结构化落盘**。

- 根目录由 `STUDYASSISTANT_DATA_DIR` 控制，默认 `~/.studyassistant/`。
- 写入使用临时文件 + 原子替换；读取失败降级返回 `ok:false` 而非抛异常。

## 理由

- 闭环的本质是**状态机**（`pending → learning → mastered`、轮次计数、已试角度集合、拆解深度）。这些是结构化、需要精确读写的状态，自然语言记忆条目无法可靠承载。
- 掌握度判定必须**确定性**（见 ADR-0002），而确定性判定要求输入是结构化的历史答题记录，不能是模型对记忆的转述。
- 会话上下文在长对话中会被压缩/丢失，用它承载「第几轮、试过哪些角度」这类精确计数不可靠。
- 方案 2 与方案 3 并非互斥：`tool:memory` 仍用于**学习者画像**（基础水平、偏好讲法、长期薄弱领域）这类模糊事实，二者分工互补。

## 后果

**正面**
- 支持「继续学上次的」，长周期学习闭环成立。
- 状态可单测（注入 tmp 目录即可），算法与 IO 解耦。
- `get_summary` 天然成为学习报告与错题本的数据源。

**负面 / 代价**
- 引入文件状态管理：需要处理并发写、损坏、版本迁移。
  - 缓解：原子替换；`schema_version` 字段预留迁移位；读取失败降级。
- 插件运行环境的可写目录假设需要验证。
  - 缓解：默认落用户主目录而非插件工程目录；环境变量可覆盖；实现后用 `agentplatform validate` + 本地冒烟验证。
- 多设备/多实例不共享进度。
  - 本期明确不做（见需求 §7），`plan_id` 已为将来同步预留。

## 备选方案

| 方案 | 放弃原因 |
|---|---|
| 仅会话上下文 | 无法跨会话续学；精确计数在上下文压缩下不可靠 |
| 平台 `tool:memory` | 承载不了结构化状态机；掌握度判定无法建立在自然语言转述上 |
